# Clash for fnos 操作手册

适用版本：**v1.3.0**。更新时间：**2026 年 10 月 7 日**。

本手册面向使用飞牛 NAS 的普通用户，说明从安装、导入订阅到日常管理的操作方法。首次使用可先完成第 1、2 章；修改分流规则、节点及其他配置时，再阅读对应章节。

Clash for fnos 是 Mihomo 内核的管理软件。软件提供配置和代理管理功能，节点及订阅需要自行准备。

## 1 安装与准备

### 1.1 使用前准备

准备以下内容：

- fnOS **1.1.3100 或更高版本**，以及可以安装应用的管理员账号。
- 一条返回 Clash／Mihomo YAML 的订阅链接，或一份可用的 YAML 配置文件。
- NAS 可以访问订阅地址。使用 all 安装包时，首次启用还需要下载 Mihomo Core。

订阅 URL、节点密码和 Controller Secret 属于私密信息，分享截图或提交问题前请遮盖。

### 1.2 选择安装包

从 [项目 Releases](https://github.com/chenpingonline/Clash-for-fnos/releases) 下载 `.fpk`。

| 安装包 | 适用设备 | 首次启用内核 |
| --- | --- | --- |
| x86_64 | 使用 x86_64 CPU 的 NAS | 内置对应架构的 Mihomo v1.19.32 |
| arm64 | 使用 ARM64 CPU 的 NAS | 内置对应架构的 Mihomo v1.19.32 |
| all | x86_64 或 ARM64 NAS | 不内置 Mihomo，按设备架构在线下载 |

已知设备架构时优先选择对应架构包。不确定时可选择 all，但需保证首次下载的网络条件。当前安装包不支持 32 位 x86 或 ARMv7。

### 1.3 安装和打开

1. 登录 fnOS，进入 **应用中心 → 手动安装**。
2. 选择下载好的 FPK，按安装向导完成安装。
3. 从 fnOS 桌面打开 **Clash for fnos**。
4. 等待内核准备完成，查看「仪表盘」和左下角连接状态。

首次启动默认使用 **Manager 托管**。all 包会先下载内核；如显示下载失败，可使用「重试启用」。仪表盘还提供官方 Core 下载与上传入口，上传时应使用页面提示的对应架构 `.gz` 文件。

**完成标志：**软件能正常打开，内核准备完成。此时还需导入并应用自己的配置，才能使用对应代理节点。

## 2 首次使用

### 2.1 导入并应用订阅

1. 点击左侧 **订阅配置**。
2. 点击 **添加订阅**，填写名称和完整的订阅 URL。
3. 首次使用可保留更新间隔；需要自动下载时勾选「自动更新」。
4. 点击 **添加订阅**，等待下载结果。
5. 在新订阅卡片上点击 **应用**，等待应用完成。

使用本地文件时，点击 **从当前电脑导入 YAML**，选择文件并导入，再点击该配置的 **应用**。

**完成标志：**配置卡片以绿色边框及名称前的圆点标记为当前配置，「代理节点」页能显示配置中的代理组和节点。

### 2.2 选择节点

1. 打开 **代理节点**，展开一个手动选择代理组。
2. 点击本组的 **延迟测试**，等待测速完成。
3. 点击要使用的节点名称，确认代理组「当前」显示已更新。
4. 返回 **仪表盘**，将「运行模式」设为 **规则**。

自动选择、故障转移等组按配置中的策略运行。日常操作主要选择手动组中的成员；一个组也可能引用另一个代理组。

### 2.3 让目标程序使用代理

按使用对象选择一种接入方式：

| 使用对象 | 操作方法 |
| --- | --- |
| NAS 上支持代理环境变量的程序 | 在仪表盘开启「系统代理」，必要时重新启动目标程序或重新登录 Shell |
| NAS 上需要透明接管的流量 | 在确认订阅可用后开启 TUN，详见第 4 章 |
| 电脑、手机等局域网设备 | 开启「允许局域网连接」，再在该设备或程序中手动填写 NAS IP 和代理端口 |
| Docker 容器 | 在容器或应用中配置可访问的 NAS 代理地址；具体接入取决于容器网络 |

**软件显示「已连接」代表管理软件已连接内核，不代表所有设备和程序都已使用代理。**

### 2.4 验证是否生效

1. 用刚配置代理的目标程序发起一次网络请求。
2. 打开 **连接**，查看目标、匹配规则及代理链。
3. 根据代理链确认流量走向，必要时检查「日志」中的连接或解析错误。

仪表盘的「查询出口 IP」反映查询请求在当前模式和规则下的出口，不保证经过页面上选中的那个代理组。

## 3 页面与基本操作

| 页面 | 主要用途 |
| --- | --- |
| 仪表盘 | 查看内核、当前配置、流量和出口；快速切换节点、运行模式、系统代理及 TUN |
| 代理节点 | 展开代理组、选择节点、测速、排序及管理 Proxy Providers |
| 订阅配置 | 添加、导入、更新和应用配置；编辑订阅增强及全局增强 |
| 配置文件 | 查看当前配置，搜索、复制、格式化及编辑托管 YAML |
| 规则 | 查看生效规则、启用或禁用规则、更新 Rule Providers |
| 连接 | 查看活动连接、命中规则与代理链，关闭连接 |
| 日志 | 查看 Mihomo 日志，按级别和关键词筛选 |
| 设置 | 管理内核、网络端口、DNS、TUN、环境变量及应用更新 |

页面右上角的 **刷新** 用于重新读取当前页面数据，不等同于更新订阅、更新内核或重启应用。

**保存方式：**设置页多数参数在修改后点击空白处自动保存，应等待保存结果；标有「应用」「保存设置」「保存并应用」的操作需点击相应按钮。增强编辑器中的草稿在保存前不会生效。

## 4 选择代理方式与运行模式

### 4.1 运行模式

入口：**仪表盘 → 运行模式**。

| 模式 | 行为 | 适用情况 |
| --- | --- | --- |
| 规则 | 按当前配置的规则决定直连、代理或拒绝 | 日常按域名、网段等分流 |
| 全局 | 使用 GLOBAL 策略处理进入 Mihomo 的流量 | 临时统一出口或排查分流问题 |
| 直连 | 进入 Mihomo 的流量使用直连 | 临时测试直连访问 |

运行模式只决定**已经进入 Mihomo 的流量**如何处理。切到全局不会自动让整个局域网都经过 NAS。

### 4.2 NAS 系统代理

入口：**仪表盘 → 系统代理**。点击旁边的齿轮可打开「系统代理设置」；详细入口为 **设置 → 环境变量设置**。

1. 确认混合代理端口已启用。
2. 开启「系统代理」或「启用代理环境变量」。
3. 按需启用「自动跟随 Mixed Port」，避免代理端口变化后地址失效。
4. 设置代理绕过地址和应用范围，点击弹窗中的 **保存**。
5. 对已有 Shell 会话重新登录，对目标程序按需重启。

此功能管理 fnOS 的代理环境变量。已有进程、Docker 容器和不读取这些变量的服务不一定会自动生效。关闭系统代理只移除本应用管理的环境配置，内核和代理端口继续运行。

### 4.3 TUN 透明接管

入口：**仪表盘 → 虚拟网卡(TUN)模式**，详细参数位于 **设置 → 虚拟网卡(TUN)设置**。

1. 先在不开启 TUN 的情况下，确认订阅、节点和代理端口可用。
2. 打开 TUN 设置，检查页面显示的可用状态。
3. 首次使用保留协议栈「跟随内核默认」及 MTU 等默认参数。
4. 如 NAS 同时使用 VPN 或其他虚拟网络，按实际需要填写「排除自定义网段」，每行一个 IPv4／IPv6 CIDR。
5. 开启 TUN，等待页面显示完成，不要在切换期间反复点击。
6. 从 NAS 目标程序发起请求，并在「连接」页检查结果。

TUN 会改变 NAS 的路由与 DNS 流向。它的局域网转发和容器覆盖范围取决于实际网络配置，不能据此认为整个家庭网络或所有 Docker 网络都已接管。

开启后网络异常时，先关闭 TUN，再检查 DNS、排除网段及节点可用性。TUN 关闭时修改详细参数会先保存为预配置，之后开启时生效。

### 4.4 供局域网设备使用

1. 进入 **设置 → 网络与端口**，确认「混合代理端口」已启用并记录端口号。
2. 开启 **允许局域网连接**，等待保存完成。
3. 在电脑、手机或具体应用中填写代理地址：**NAS 的局域网 IP + 实际代理端口**。
4. 发起请求，在「连接」页检查是否进入 Mihomo。

例如 NAS 地址为 `192.168.1.10`，实际混合端口为 `7890`，HTTP 代理服务器填写 `192.168.1.10`、端口填写 `7890`。请替换为自己的值。

`127.0.0.1` 指向发起请求的设备自身。在电脑或普通桥接容器里填写它，并不会连接 NAS。代理端口应仅提供给需要使用的网络，不要直接暴露到公网。

## 5 管理订阅配置

### 5.1 更新和应用的区别

| 操作 | 结果 |
| --- | --- |
| 更新 | 重新下载远程订阅内容；是否立即生效取决于当前配置的自动应用设置 |
| 应用 | 将所选配置与增强、用户设置合并，校验后加载到内核并同步启动配置 |
| 编辑 → 订阅信息 | 修改名称、URL、更新间隔及自动更新选项；修改 URL 后需再更新下载内容 |
| 删除 | 删除软件中的该配置及其增强；操作前保存需要保留的内容 |

自动更新按「直连 → 当前 Mihomo mixed-port → 系统 HTTP/HTTPS 代理」尝试下载。卡片上的「最近下载」用于查看本次路径与结果。

### 5.2 自动更新

1. 打开订阅的 **编辑 → 订阅信息**。
2. 勾选 **自动更新**，设置更新间隔，单位为分钟，最小为 **5 分钟**。
3. 希望当前订阅更新后立即生效时，勾选 **当前配置更新后自动应用**。
4. 点击 **保存修改**。

自动应用针对当前正在使用的配置。其他订阅更新后不会仅因这个选项而切换成为当前配置。

流量、到期时间等信息由订阅响应提供；没有显示不代表订阅无效，也不等于软件已经测得真实套餐余量。

### 5.3 导入本地配置

**当前电脑上的文件：**点击页面顶部的 **从当前电脑导入 YAML**，填写名称、选择文件并导入，再在配置列表中应用。

**NAS 上的文件：**查看页面底部的 **本机 Mihomo 配置**。

1. 需要读取 NAS 用户文件夹时，按页面提示进入 fnOS **系统设置 → 应用 → Clash for fnos → 访问权限** 授权目录。
2. 返回软件，点击 **重新扫描**。
3. 在可读取的候选文件上点击 **导入** 或 **导入并应用**。

“当前电脑”是打开 fnOS 网页的设备；NAS 文件使用扫描入口，二者不是同一个文件位置。

### 5.4 切换订阅

点击目标配置的 **应用**，等待完成后确认当前标记。各订阅的规则开关记录和增强分别保存；改名不会改变所属记录，重新添加一个订阅则会生成新的配置身份。

## 6 查看和修改规则

### 6.1 查看生效规则

入口：**规则**。

列表显示序号、规则内容、类型、目标策略及启用状态。可按内容、类型或策略搜索。规则来自订阅及用户增强，软件默认不会额外生成一套代理组和分流规则。

规则按顺序匹配。禁用一条规则后，请求会继续尝试后续规则；不会自动将它改为直连。

### 6.2 暂时跳过一条规则

1. 搜索目标规则，核对内容和目标策略。
2. 关闭该行的 **启用** 开关。
3. 等待操作完成，确认条目显示灰色删除线。
4. 用新的网络请求验证后续规则的处理结果。

需要恢复时，重新开启同一开关。

开关状态按订阅独立保存，订阅更新、重载配置、重启内核或应用后会恢复。匹配依据包含规则类型、内容及目标策略；规则内容或重复数量变化时会跳过恢复，防止禁用错误条目。

关闭 `RULE-SET` 会跳过整个规则集引用。关闭 `MATCH` 等兜底规则可能改变剩余流量的去向。当前内核不支持开关时，操作不可用。

### 6.3 长期新增或排除规则

入口：**订阅配置 → 对应订阅的编辑 → 编辑规则**。

以新增 `example.com` 及其子域名的直连规则为例：

1. 「规则类型」选择 **域名后缀 · DOMAIN-SUFFIX**。
2. 「规则内容」填写 `example.com`。
3. 「代理策略」选择 **DIRECT**。
4. 「添加位置」选择 **前置**，点击 **添加规则**。
5. 确认列表中出现新增条目，点击 **保存并应用**。

可视化输入框只填写域名等匹配内容，完整规则在高级 YAML 中才写成 `DOMAIN-SUFFIX,example.com,DIRECT`。

前置规则优先于原始订阅规则匹配；后置规则放在原始规则之后。如果原始列表已包含 `MATCH`，后置规则可能永远不会命中，应按目的改为前置。

原始规则点击红色 **排除**，排除后可点击绿色 **恢复**；自定义规则使用 **删除**。这些都是草稿变更，需要保存后生效。**重置本订阅增强**只清除此编辑器的前置、后置和排除记录，确认后仍需保存。

高级模式示例：

```yaml
prepend:
  - DOMAIN-SUFFIX,example.com,DIRECT
append: []
delete: []
```

如需用 `delete` 排除原始规则，应填写原始规则全文，类型、内容和策略都需一致。

### 6.4 更新规则集

入口：**规则 → 规则集**。

在对应 Rule Provider 上点击 **更新**，或点击 **全部更新**。这里更新的是配置引用的规则集资源，不是重新下载整份订阅。当前配置没有 Rule Provider 时，列表为空。

## 7 编辑节点与代理组

### 7.1 日常选择和测速

入口：**代理节点**。

- 点击代理组标题展开或收起；顶部可全部展开或收起。
- 点击节点名称切换手动选择组的成员；点击节点延迟可单独测速。
- 本组或顶部的「延迟测试」可批量测速。
- 排序支持默认、按延迟、按名称；组内还可按名称筛选并隐藏超时节点。

测速结果取决于测试地址、网络与节点状态。超时不一定代表节点完全不可用，延迟也不等同于下载速度。

「代理节点」顶部的 **策略组** 按钮实际用于管理 **Proxy Providers 代理集合**，可执行健康检查、单独更新或全部更新。它与订阅菜单中的「编辑代理组」功能不同。

### 7.2 添加自定义节点

入口：**订阅配置 → 编辑 → 编辑节点**。

1. 在输入区按行粘贴有效节点 URI，或粘贴 Base64 编码的节点列表。
2. 选择前置或后置，点击添加按钮。
3. 核对节点名称、类型及服务器，避免与已有节点或代理组重名。
4. 点击 **保存并应用**，到「代理节点」页确认节点出现。

新增节点会加入首个手动选择代理组。排除原始节点时，同时移除代理组中对该节点的直接引用。

需要填写完整协议参数时，切换 **高级**，或从新增条目的 **编辑** 进入 YAML 编辑。示例：

```yaml
prepend:
  - name: 我的自定义节点
    type: trojan
    server: node.example.com
    port: 443
    password: 请替换为实际密码
    sni: node.example.com
    udp: true
append: []
delete: []
```

示例仅说明写法，服务器和密码需要替换。节点增强中的 `delete` 填写原始节点名称，不填写 URI。

### 7.3 添加代理组

入口：**订阅配置 → 编辑 → 编辑代理组**。

1. 选择代理组类型，填写唯一的组名。
2. 在「引入代理」中添加已存在的节点或代理组；使用代理集合时填写对应的集合引用。
3. 自动测试类代理组按需设置健康检查地址和间隔，其他参数在「更多设置」中调整。
4. 选择前置或后置并添加，点击 **保存并应用**。
5. 到「代理节点」页查看新组；需要让流量使用它时，在规则增强中将目标策略设为该组。

| 类型 | 用途 |
| --- | --- |
| select | 手动选择成员 |
| url-test | 按健康检查结果自动选择 |
| fallback | 按顺序选择可用成员，故障时转移 |
| load-balance | 按配置的负载均衡策略使用成员 |

引用必须存在，代理组不能引用自己。排除一个原始代理组时，应同步调整规则和其他组的引用，否则最终配置可能校验失败。

### 7.4 筛选与恢复

三类增强编辑器均提供搜索及「全部」「前置」「订阅原始」「后置」「已排除」筛选。红色表示排除或删除，绿色表示恢复。新增条目可编辑及排序；标题旁的 **问号** 提供当前功能的示例，高级模式中也可查看。

## 8 使用扩展覆写与脚本

### 8.1 选择修改入口

| 目的 | 建议入口 |
| --- | --- |
| 新增、排除或排序规则 | 编辑规则 |
| 添加自定义节点 | 编辑节点 |
| 添加或排除代理组 | 编辑代理组 |
| 固定覆盖其他配置字段 | 扩展覆写配置 |
| 按条件筛选或生成配置 | 扩展脚本 |
| 让每份配置都使用相同修改 | 全局扩展覆写配置／全局扩展脚本 |

单订阅入口位于对应配置的 **编辑** 下拉菜单。全局入口位于「订阅配置」页配置列表下方。

### 8.2 扩展覆写配置

只填写需要修改的 YAML 片段，无需粘贴整份订阅。例如：

```yaml
tcp-concurrent: true
profile:
  store-selected: true
```

点击 **保存并应用** 后校验并加载。对象递归合并，未填写字段保留；数组整体替换。直接写 `rules:` 会替换整个规则列表，添加几条规则应优先使用「编辑规则」。

### 8.3 扩展脚本

脚本定义 `main(config, profileName)`，返回修改后的配置对象。以下示例将一条直连规则放到最前面并避免重复：

```javascript
function main(config, profileName) {
  const rule = "DOMAIN-SUFFIX,example.com,DIRECT";
  const rules = config.rules || [];
  config.rules = [rule, ...rules.filter(item => item !== rule)];
  return config;
}
```

不要使用 `module.exports` 或 `export default`。脚本在沙箱中执行，不提供浏览器或 Node.js API，执行时间上限为 **5 秒**。

### 8.4 保存范围与执行顺序

单订阅增强保存后会应用**正在编辑的那份订阅**，可能切换当前配置。全局增强保存后重新应用当前配置；没有当前配置时只保存，之后应用配置时再使用。

最终配置处理顺序为：

1. 原始订阅。
2. 规则、节点、代理组增强。
3. 全局覆写 → 全局脚本。
4. 对应订阅覆写 → 对应订阅脚本。
5. 已保存的 Core 用户设置，以及启用的 DNS／Hosts 覆盖。
6. 校验并应用。

同一字段被多处设置时，以后续处理结果为准。增强与原始订阅分开保存，更新订阅后会重新应用。

如出现「已保存，但应用失败」，增强文件可能已经保存。先按错误提示修正，再应用；不要仅因内核仍使用旧配置，就认为增强文件没有变化。

## 9 查看和编辑配置文件

### 9.1 查看和搜索

入口：**配置文件**。

页面显示配置路径、PID 和托管／外部模式。默认紧凑预览，可点击「格式化／压缩」切换。搜索框支持全文搜索，按 **Enter** 跳到下一项，按 **Shift + Enter** 跳到上一项，也可点击箭头按钮。

超长行默认只显示开头，点击 **展开更多** 查看后续内容。折叠和预览格式不会删减实际配置；「复制配置」复制完整原文。左右内容被截断时使用底部横向滚动条。

### 9.2 修改当前启动 YAML

此功能用于 **Manager 托管**，外部 Core 配置保持只读。

1. 点击 **编辑配置**。
2. 修改 YAML，可用「格式化」「压缩」整理，也可撤销格式调整。
3. 点击 **保存并应用**，等待校验和应用结果。
4. 返回仪表盘或配置页确认内核状态。

保存会备份并校验，应用失败时回滚。Controller 地址和 Secret 保留当前连接设置。

如果编辑期间发生订阅切换或配置更新，保存会被拒绝。先将草稿复制到安全位置，重新打开编辑器，再合并修改。

退出时点击 **放弃修改**；草稿有变化会弹出确认，可选择继续编辑。

### 9.3 哪些修改可以长期保留

| 修改方式 | 更新并应用订阅后的行为 |
| --- | --- |
| 直接编辑启动 YAML | 可能被重新生成的配置覆盖 |
| 对应订阅的增强、覆写或脚本 | 重新应用该订阅时继续参与生成 |
| 全局覆写或脚本 | 应用各配置时参与生成 |
| 设置页保存的 Core 用户设置 | 对应设置会合并到生成的配置 |
| 规则页的开关状态 | 在对应订阅中匹配并恢复 |

需要长期增删规则时，使用订阅的「编辑规则」。仅修改 YAML 的字段值，不会自动登记为设置页中的用户偏好。

## 10 设置内核与网络

### 10.1 管理内核

入口：**设置 → Mihomo Core 设置 → 内核管理**。

| 操作 | 说明 |
| --- | --- |
| 启动内核 | 启动托管 Mihomo |
| 停止内核 | 停止托管 Mihomo，管理页面继续可用；依赖它的代理连接中断 |
| 重启内核 | 重启托管 Mihomo，连接会短暂中断 |
| 检查更新 | 检查 Mihomo 官方版本，随后可选择更新内核 |
| Core 运行方式 | 切换 Manager 托管或外部 Mihomo，点击「应用」生效 |

更新时勾选「更新后重启内核」可立即启用新版；不勾选则下次启动内核生效。失败时查看错误信息并使用「重试更新」。应用版本与 Mihomo 内核版本独立更新。

手动停止内核后，本次管理页面仍可使用；再次启动应用时，托管模式会自动准备并启用内核。

需要重启后保留手动选中的代理组成员，可启用 **重启 Core 后恢复策略组选择**，恢复限于仍然有效的选择。

### 10.2 外部 Mihomo 与连接设置

已有独立 Mihomo 服务时，可在「Core 运行方式」选择 **外部 Mihomo** 并应用。软件停止自己的托管内核，连接已有服务；外部内核的启停、更新由原有服务管理。

进入 **Mihomo Core 设置 → 连接管理**：

1. 优先使用自动检测。
2. 自动检测失败时关闭「自动检测」，填写 NAS 主机可访问的 Controller 地址及 Secret。
3. 点击 **保存连接设置**，再点击 **测试连接**。

Secret 留空表示保留已有值，需要移除时使用「清除已保存的 Secret」。Controller 是管理 API，不能填成 HTTP／SOCKS 代理端口。

### 10.3 端口与网络选项

入口：**设置 → 网络与端口**。

- **Controller API：**内核管理接口，托管模式由应用使用本机地址连接。
- **混合代理端口：**同时接收 HTTP 与 SOCKS5，通常优先使用它。
- **其他端口：**按需求提供独立 SOCKS5、HTTP、Redir 或 TProxy 入站；不可用选项以页面显示为准。
- **允许局域网连接：**允许其他设备使用已启用的代理端口。
- **全局 IPv6：**控制内核接收和处理 IPv6 流量。
- **统一延迟：**统一测速算法，便于不同协议间比较。

修改后点击空白处，等待保存完成。端口不能与其他服务冲突。Core 已停止时可编辑托管启动配置，完成后再启动内核。

### 10.4 延迟测试设置

入口：**Mihomo Core 设置 → 延迟测试**。

选择预设或自定义测试地址，设置 **1～30 秒**超时。新安装默认使用 Cloudflare HTTP 测试地址。修改后自动保存，后续节点测速使用新设置。

### 10.5 DNS 设置

入口：**设置 → DNS 与解析**。

「DNS 覆写」默认关闭。关闭时只保存模板，不写入当前启动配置；需要覆盖订阅 DNS 时才开启。

| 标签页 | 设置内容 |
| --- | --- |
| 基础设置 | 启用 DNS、监听地址、Fake IP／Redir Host、IP 范围及 IPv6 DNS 等 |
| 解析服务器 | 默认、常规、回退、代理节点及直连 DNS 服务器 |
| Fake IP 与域名策略 | Fake IP 过滤及指定域名的 DNS 服务器 |
| 回退过滤 | GeoIP 国家代码、IP 网段及回退域名 |
| Hosts 映射 | 指定域名的静态地址 |

列表通常每行一个值。域名服务器策略和 Hosts 使用 `键 = 值`，多个值用英文分号分隔，例如：

```text
# 域名服务器策略输入框中填写下面这一行，不包含此注释
+.example.com = https://dns.alidns.com/dns-query
```

```text
# Hosts 输入框中填写下面这一行，不包含此注释
nas.example.com = 192.168.1.10
```

TUN 开启 DNS 劫持时应同时确认 Mihomo DNS 可用。全局 IPv6 与 IPv6 DNS 解析是不同设置，不要只改其中一项就认为所有 IPv6 行为已改变。

### 10.6 GEO 数据

入口：**Mihomo Core 设置 → GEO 数据**。

查看 GeoIP、GeoSite、Country MMDB 和 ASN MMDB 状态。缺失资源可点击「下载」；点击「立即更新」更新数据。需要自动更新时选择周期，再点击 **保存设置**。外部模式等不支持操作的情况，按页面提示处理。

### 10.7 环境变量与外观

**设置 → 环境变量设置**可管理启用状态、跟随 Mixed Port、代理绕过及写入范围。支持的范围包括系统登录环境、登录 Shell 与 Bash 交互环境，主要对新进程及新登录会话生效。

**设置 → 其他设置**可更换软件图标。应用外观跟随 fnOS 宿主主题，软件中没有独立的主题选择按钮。

## 11 查看连接与日志

### 11.1 活动连接

入口：**连接**。

列表提供目标、进程、匹配规则、代理链及上传／下载量。进程字段是否完整取决于内核能否获得相关信息。点击行末 **×** 关闭单个连接；**关闭全部**会中断当前全部连接，目标程序可能自行重连。

修改节点或规则后，已有连接不一定立即改走新策略。需要验证时，重新发起请求，必要时关闭对应旧连接。

### 11.2 Mihomo 日志

入口：**日志**。

1. 选择日志级别与显示行数。
2. 输入关键词筛选并查看高亮内容。
3. 根据阅读需要开启「自动换行」。
4. 点击 **停止** 暂停实时读取，点击 **继续**恢复；这不会停止内核。
5. 需要重新观察问题时，可点击 **清空** 后再次触发问题。清空会删除软件记录的历史日志，需要保留的排查信息应先复制保存。

搜索范围是当前读取的最近日志，不是无限历史。普通排查先用 `info`，需要更多细节时再使用 `debug`。

### 11.3 应用启动日志

应用打不开或页面空白时，使用 SSH 登录 NAS：

```bash
sudo tail -n 200 /var/apps/clash-for-fnos/var/clash-for-fnos.log
```

需要观察重新启动过程：

```bash
sudo tail -f /var/apps/clash-for-fnos/var/clash-for-fnos.log
```

然后在 fnOS 应用中心停止并重新启动应用，按 **Ctrl+C** 结束跟踪。此文件是 Web 服务及 Root Helper 的启动日志，与应用内的 Mihomo 日志不同。

## 12 升级与备份

### 12.1 升级应用

1. 在 **设置 → 更新设置** 查看当前版本，点击 **检查更新**。
2. 有新版时查看 **更新内容**，点击 **下载更新**进入发布页。
3. 下载适用架构的 FPK，在 fnOS **应用中心 → 手动安装**中安装新版。
4. 升级完成后检查内核连接、当前订阅、节点和 TUN 状态。

软件提供版本检测及下载入口，FPK 安装由 fnOS 应用中心完成。启用「更新提示」后，软件启动时检查版本，并在有新版时提示。

升级保留已有配置和数据，all 包升级时保留已有内核；TUN 在升级期间可能短暂释放并重新建立路由。不要用卸载再安装代替正常升级。

### 12.2 备份重要内容

v1.3.0 没有一键导出全部用户数据的操作入口。可按需备份：

- 使用 **配置文件 → 复制配置**保存当前完整 YAML。
- 在各增强编辑器中复制高级 YAML、覆写内容及脚本。
- 记录订阅名称、更新选项及必要的网络设置。
- 需要完整备份时，由熟悉 NAS 文件管理的用户备份应用配置目录；`${TRIM_PKGETC}/profiles/` 保存订阅及增强，`${TRIM_PKGETC}/rule-state.json` 保存规则开关记录。

仅复制当前 YAML 无法还原全部订阅身份、增强和规则状态。备份包含订阅地址、Secret 和节点密码，应保存在受保护的位置。

## 13 常见问题与故障处理

### 13.1 页面打不开或空白

1. 核对 fnOS 是否满足 **1.1.3100** 最低版本。
2. 确认应用中心显示应用正在运行。
3. 按第 11.3 节查看启动日志。
4. 启动日志正常时，检查浏览器开发者工具的 Console 报错及 Network 失败请求。

### 13.2 内核未连接

先查看仪表盘中的准备或错误提示。托管模式到「内核管理」启动内核；all 包下载失败时重试或使用官方文件上传。外部模式到「连接管理」核对 Controller 和 Secret，并测试连接。

### 13.3 订阅更新失败

检查完整 URL、NAS 的 DNS 和网络，并查看卡片「最近下载」及错误提示。确认订阅返回的是 Clash／Mihomo YAML，而非网页、登录页面或无法直接使用的节点列表。订阅下载在 NAS 执行，电脑能打开链接不代表 NAS 一定能下载。

### 13.4 导入后没有代理组或节点

确认已经点击 **应用**，而非仅添加或导入。检查配置是否包含有效的 `proxies`、`proxy-groups` 或 `proxy-providers`。软件默认不替只有节点的文件自动生成完整分流方案；需要完整配置，或通过增强补充代理组及规则。

### 13.5 节点测速超时

检查订阅是否过期及节点信息是否有效；换一个节点或测试地址，适当增加超时后重试。用真实目标请求及「连接」「日志」共同判断，不能只凭一次测速下结论。

### 13.6 显示已连接但目标程序仍然直连

依次核对：目标程序是否配置了代理、实际代理端口是否启用、局域网访问是否允许、当前运行模式及命中规则。NAS 环境变量不会自动更改电脑代理；Docker 和已有服务也不一定读取新环境变量。

### 13.7 提示端口冲突

到 **设置 → 网络与端口**更换冲突端口，并同步客户端的代理地址。已有外部 Mihomo 占用端口时，可选择外部模式，或为托管 Core 设置不同端口；软件不会自动停止用户的外部服务。

### 13.8 修改 YAML 后更新订阅又恢复了

直接编辑启动 YAML 会被后续订阅生成流程覆盖。使用对应订阅的规则、节点、代理组增强，或扩展覆写／脚本保存长期修改，具体见第 6～9 章。

### 13.9 关闭的规则没有恢复禁用状态

确认当前是否是原来那份订阅；检查规则内容、目标策略或重复数量是否发生变化。变化时软件会跳过匹配，需在新的规则上重新设置。后台恢复可能需要等待下一次检查，再刷新规则页确认。

### 13.10 新增规则没有命中

确认已保存并应用、运行模式为「规则」，以及目标程序流量确实进入内核。检查前面是否已命中其他规则或 `MATCH`，按需要把规则移到前置。已有连接应重新建立后再验证。

### 13.11 配置或增强校验失败

检查 YAML 缩进、规则全文、节点与组名重复、引用是否存在，以及脚本是否返回配置对象。排除代理组后仍有规则引用它，是常见原因。按具体错误修正，不要反复重复应用同一份无效内容。

### 13.12 提交问题时提供什么

在 [GitHub Issues](https://github.com/chenpingonline/Clash-for-fnos/issues) 提供：应用版本、Mihomo 版本、fnOS 版本、设备架构、托管／外部模式、复现步骤、预期和实际结果，以及相关错误日志。涉及网络时补充 TUN、Docker 或 VPN 使用情况。遮盖订阅 URL、Secret、密码及其他私密信息。

## 14 术语与帮助

| 术语 | 含义 |
| --- | --- |
| Mihomo Core | 实际处理代理、规则和网络请求的内核 |
| Controller | 软件控制内核使用的管理 API |
| Secret | Controller 的访问凭据 |
| Mixed Port | 同时提供 HTTP 与 SOCKS5 的代理端口 |
| 代理组 | 节点或其他代理组的集合，规则可以将它作为目标策略 |
| Proxy Provider | 从资源文件或远程地址加载节点的代理集合 |
| Rule Provider | 从资源文件或远程地址加载规则的规则集 |
| DIRECT | 直连策略 |
| REJECT | 拒绝策略 |
| MATCH | 匹配剩余请求的兜底规则 |
| 订阅增强 | 与原始订阅分开保存，在应用时合并的修改 |
| TUN | 通过虚拟网卡和路由接管流量的方式 |
| GEO 数据 | 基于地区、域名分类等进行匹配的数据资源 |
