# TUN 主动重启、状态协调与实际网卡验证

日期：2026-10-31。共享源码版本 1.6.23；以下记录为打包前完成的自动检查与隔离 Linux 验证。fnOS 包构建与真实设备验证单独记录，不由这些结果推定通过。

## 行为

- 托管 Core 开启 TUN：候选配置和 DNS 依赖校验 → 写入可回滚配置 → 有序重启 Core → 等待 Controller → 检查实际 TUN 网卡 → 提交。外部 Core 不由应用主动重启。
- 关闭优先热切换；Core 已停止时可保存关闭意图、修改详细参数，不启动 Core。
- 详细设置与订阅／启动配置应用复用相同的准备元数据、DNS 依赖检查和网卡确认。Core、配置及 TUN 操作通过同一网络操作锁串行协调；失败沿原事务恢复配置与运行状态。
- 状态明确区分保存的开启设置、Controller 返回状态和实际网卡状态。检查 Core 所在网络命名空间与 Helper 一致，并检查指定设备的 tun_flags（必须为 TUN，不能是普通网卡或 TAP）和 UP 标志。
- 统一状态 GET/SSE 供仪表盘、设置页和弹窗共享；操作变化即时通知，低频检测外部变化。前端共享一条订阅，离开页面释放；慢响应不会覆盖较新的操作事件，断连显示未知且保留开启意图。
- 启动先确认已有状态；健康 TUN 不再先关后开。明确停止的 Core 不由启动对账重新启动，也不等待其 Controller。暂时未知、启动或重启中的状态不清除用户设置。
- DNS 劫持要求 Mihomo DNS 已开启；Fake-IP 地址范围检查 CIDR。不会替换现有 DNS 或系统 DNS 设置，缺项提示沿用内核默认值。

## 隔离真实运行

使用本地 Colima Linux 容器、NET_ADMIN 和仓库附带的 Mihomo v1.19.33。配置、用户与数据为专用夹具。TUN 自动路由、自动重定向均关闭；该环境验证真实内核网卡及 Core 生命周期，不验证物理宿主接管。

- 快捷开启返回 `managed-restart`，Core PID 改变，统一状态显示 Controller 开启且真实 `Meta` 为 UP/TUN。
- 快捷关闭返回 `patch`，PID 保持不变，实际网卡释放；关闭验证保留切换前设备名，避免 Controller 关闭后不返回设备名造成漏检。
- 详细设置从关闭改为开启同样主动重启并确认网卡。
- 开启 DNS 劫持但关闭 Mihomo DNS 时，启用在重启之前被阻止，Core PID 未改变；现有 DNS 未改写。
- 直接在容器中删除 `Meta` 后，Controller 仍返回开启，但状态与界面均显示“实际网卡尚未就绪”，不会报告就绪；通过关闭再开启恢复。
- 停止 Core 后仍保存 TUN 开启设置，运行状态显示未知，偏好文件保持不变；离线修改 MTU 不启动 Core，也不清除开启意图。
- Core 停止时关闭 TUN 返回 `saved-only`，随后启动 Core 遵从保存的关闭设置。
- 在测试容器启动前提供可用 TUN 设备，以开启设置重新启动完整服务，恢复真实 TUN；健康状态确认后 PID 保持稳定，不执行额外的先关后开循环。
- Computer Use 复查快捷关闭／开启、重启期间禁用、详细弹窗三项状态、网卡消失警告、Core 停止时保留意图和最终就绪状态；截图已目视检查。

运行输出、JSON 状态与截图保存在 `.cache/tun-coordination/`。验证后清理临时容器与专用端口转发。

未在真实 fnOS 设备安装或升级；未验证完整自动路由、系统 DNS、VPN、局域网转发及物理宿主流量。失败回滚的缺失网卡场景由 Helper/Controller 夹具回归测试覆盖；真实容器另行验证网卡丢失的识别与手动恢复。FPK 构建和设备测试结果另行记录。
