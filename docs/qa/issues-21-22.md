# Issues #21 / #22 开发与验证记录

日期：2026-10-31。本记录覆盖公共仓库 Clash-Manager 1.6.22 的功能开发验证；FPK 的采用提交、版本和交付审计以 fnOS 仓库的 `upstream.lock`、manifest 与构建审计记录为准。

## 实现

- #22：在设置页及仪表盘 TUN 弹窗提供只读诊断、重新检测、复制诊断信息和显式修复入口。设备探测检查字符设备、设备号和 TUNGETFEATURES；读取 Core 实际 NET_ADMIN 能力。修复仅执行固定路径的系统 `modprobe tun`，确认驱动注册后补建缺失节点，复查结果，不改变 TUN 启用配置、既有节点权限或路由。Docker 部署不提供修复。
- #21：独立入口定义保存于现有 `core-user-settings.json` 的独立字段，支持 HTTP、SOCKS5、Mixed、显式监听地址、端口、目标和独立账户。配置生成不注入管理元数据字段，使用 YAML 注释识别生成入口，保留订阅入口及已有 YAML 锚点/别名。
- 订阅更新先合并入口，再使用现有校验、激活、提交和回滚流程。目标按配置内节点/策略组名称引用；不存在时不生成该入口，保留启用意图并在界面显示失效，同名目标恢复后自动恢复。动态 provider 节点通过引用 provider 的策略组选择。
- 自定义 listeners 纳入 TCP/UDP 冲突与占用预检，包含端口范围、当前 Core 已占用端口及 IPv4/IPv6 通配地址判断。

## 隔离运行验证

在本地 Colima Linux 容器中运行当前源码构建的 Helper/Web 和仓库自带 Mihomo v1.19.33，测试数据与本地订阅服务均为专用夹具，不使用正式订阅或账户。

- 以 Linux 部署模式运行原生修复流程：初始驱动已注册、`/dev/net/tun` 缺失，点击修复后创建 root:root / 0600 的字符设备 10:200；UI 从不可用变为可用，配置中 TUN 仍为关闭。
- 设置自动路由/自动重定向关闭后，真实 TUN 开启成功并创建内核接口，关闭后确认停用。
- 真实独立 Mixed 入口同时完成 HTTP/SOCKS5 转发；单独 HTTP、SOCKS5 协议也完成转发。
- 使用本地 SOCKS5 上游夹具区分 node-v1/node-v2，经真实远程订阅下载、应用、更新并应用流程修改同名节点的连接参数，独立入口随之转发到 node-v2；订阅入口和另一个 GUI 入口均保留。
- 将目标改名时，只移除对应监听入口，偏好仍保留 enabled=true；同名目标恢复后入口自动恢复。
- 独立入口 HTTP/SOCKS5 认证通过，HTTP 无认证请求返回 407。
- 完整服务重启后，偏好文件字节完全一致，独立入口、订阅入口和目标失效状态均保留。
- Computer Use 验证空状态、创建、保存、重开、端口冲突、取消草稿、失效目标、诊断复制、TUN 修复和快捷开关状态；复查常规与 390px 窄窗口，修复启用标签换行并固定长列表保存/取消操作栏。

本地详细输出和截图位于 `.cache/issues21-22/`。测试容器与端口转发在验证后清理。
