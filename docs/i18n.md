# 多语言维护 / Translation maintenance

[中文 README](../README.md) · [English README](../README.en.md)

界面提供简体中文（`zh-CN`）、English（`en-US`）与跟随系统。在设置页右上角的「界面语言」中切换，浏览器保存语言偏好；跟随系统按浏览器语言匹配，中文采用简体中文，其余采用英文。切换只更新显示，不重载配置或提交用户设置。

The interface offers Simplified Chinese (`zh-CN`), English (`en-US`) and Follow system. The language selector is at the top right of the Settings page. The browser stores the preference; system mode selects Chinese for Chinese browser locales and English otherwise. Switching changes presentation without reloading configuration or submitting user settings.

## 文件与使用 / Files and usage

- `web/src/services/i18n.ts`：响应式语言选择、持久化与文案翻译 / Reactive selection, persistence and message translation.
- `web/src/locales/zh-CN.json`：中文源文案 / Chinese source messages.
- `web/src/locales/en-US.json`：同一组键的英文翻译 / English translations with matching keys.
- `web/src/locales/message-params.json`：允许继续翻译的应用文案参数；节点名称等参数不加入 / Application-owned parameters eligible for nested translation; proxy names and other user data are excluded.
- `web/src/components/LanguageSelect.vue`：设置页的语言选择器 / Language selector in Settings.
- `web/scripts/check-i18n.mjs`：语言包、参数及前端文案覆盖检查 / Catalog, parameter and frontend source coverage checks.

这里使用中文源文案作为消息 ID，不增加第三方运行依赖。在模板显示处调用 `t()`；状态与 API 契约保持原文，因此已有提示也能即时切换。较长的动态状态可按 `{arg0}` 等参数化模板匹配；优先使用明确的消息键与参数。

Chinese source text acts as the message ID without an additional runtime dependency. Call `t()` at presentation boundaries; state and API contracts retain source messages so existing feedback can switch immediately. Dynamic status messages can match parameterized `{arg0}` templates; explicit keys and parameters are preferred for new messages.

```vue
<script setup lang="ts">
import { t } from '@/services/i18n'
</script>

<template>
  <button>{{ t('保存') }}</button>
  <span>{{ t('编辑 {arg0}', { arg0: profile.name }) }}</span>
</template>
```

新增文案时，同时在两个语言包添加相同的键；英文保留相同的 `{argN}` 参数。复用已有术语。Go 返回的新增界面错误或进度消息也应添加到语言包；Go 的 `%s`、`%d`、`%w` 等格式参数按出现顺序转换成 `{arg0}`、`{arg1}`。嵌套的应用错误才加入 `message-params.json`；名称、地址、配置内容和上游诊断参数保持原样。

For each new message, add matching keys to both catalogs and retain the same `{argN}` placeholders. Reuse established terms. Add application-owned Go API errors/progress to the catalogs too, converting Go format arguments in order to `{arg0}`, `{arg1}`, etc. Add only nested application-message parameters to `message-params.json`; names, addresses, configuration and opaque upstream diagnostics stay unchanged.

不要对节点名、订阅名、规则内容、策略名称、YAML、日志正文、路径或输入值调用 `t()`。辅助标签可以翻译，但实际选择值和提交的数据不能翻译。内置帮助示例可以提供英文示例；用户配置原文保持完整。

Do not translate proxy/profile names, rule content, policy names, YAML, log bodies, paths or input values. Translate surrounding labels while preserving selected values and submitted data. Built-in help can show translated illustrative examples; user configuration remains intact.

API 本身保留中文消息；界面翻译应用自身的错误、能力说明与操作进度。Mihomo、操作系统与其他外部组件的原始诊断、日志，以及历史更新日志继续保留原文。

API messages retain Chinese source text. The interface translates application-owned errors, capability descriptions and progress. Original diagnostics/logs from Mihomo, the OS and other external components, and historical changelog content remain in their original language.

## 验证 / Verification

```sh
npm --prefix web run i18n:check
npm --prefix web run check
```

检查包含：键集合一致、英文无遗漏、参数一致、前端文案覆盖、语言持久化、系统语言匹配、即时更新、嵌套错误和用户数据保留。浏览器验收需检查登录、导航、设置与帮助弹窗，确认英文较长文案不遮挡操作。原生 fnOS 与 Docker 共用界面，但界面验证不能替代设备上的 TUN、DNS 或安装升级验收。

Checks cover catalog parity, English coverage, placeholders, frontend source messages, persistence, system detection, live updates, nested errors and preservation of user data. Browser acceptance should cover login, navigation, settings and help dialogs, including longer English text. Shared UI verification does not replace real-device TUN, DNS or installation/upgrade acceptance.
