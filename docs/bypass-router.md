# 旁路由检查与监控

本页是现有 TUN 能力的只读诊断页，不提供单独的旁路由启停开关，不修改 TUN、DNS、系统转发、NAT 或其他防火墙规则。设置仍在原有 TUN/DNS 页面操作。

## 检查内容

- 启动配置中显式设置的 TUN、Auto Route、Auto Redirect、DNS 监听、DNS 劫持和排除网段。缺失字段显示待验证，不拿界面默认值作为配置证据。
- Controller 返回的实际 TUN enable 状态，和启动配置分别展示。Controller 不可用时显示待验证。
- Linux 的 IPv4 转发状态和只读 nftables 规则摘要。工具缺失、权限不足和非 Linux 环境显示待验证。转发/NAT 数量不能证明具体链路放行，也不代表必须添加额外 NAT；未检查 iptables legacy 等其他防火墙实现。
- 当前 Mihomo 连接按局域网源 IP 汇总，排除 NAS 自身地址。只有 metadata.type 为 TUN 的连接才算 TUN 接管证据；HTTP/SOCKS 等显式代理流量不混为透明代理。流量值只累计当前仍存在的连接，不是设备全生命周期用量或速率。

每 10 秒刷新，可手动刷新。某一数据源失败不会阻止其他检查展示；失败来源的旧数据清除，避免把过期证据继续显示为当前状态。

## 验证设备

选择 NAS 接入网卡，按显示的 IPv4 和网段在设备侧配置网关。只有 NAS 已提供可达 DNS 服务时，设备 DNS 才指向 NAS。然后在设备上访问网站，观察是否出现该源 IP 的 TUN 连接、命中规则及出口链。

未看到连接可能是没有活动流量、连接已结束、源地址被 NAT 改写或未接管，不能据此认定不支持旁路由。已观察到某个 TUN 连接也不代表所有流量都被接管；IPv6、同网段通信和被排除的目的地址仍可能绕过。

此前未发布的控制版原型的系统写入、配置覆盖、设备策略编译、生命周期钩子及写 API 已移除。若曾手动运行该开发原型且仍留有 bypass-runtime.json，检查页只提醒使用旧构建停止恢复，不会自动处理该记录。
